# 标注拖拽阈值必须按屏幕像素判断

## 约束

截图覆盖层里判断"这次拖拽是不是有效落笔"，要用**屏幕像素**换算后再比阈值，不能直接拿图像坐标的差值比。

## 原因与后果

覆盖层区分两套坐标：图像空间（选中区域最终导出的像素）与视口/屏幕空间（用户实际拖动距离）。两者差一个缩放系数 `stage.zoomScale()`：

- 小图编辑时图片会被放大到整窗显示，缩放系数可达数百（例如 1×1 的图放大到 720×720）；
- 若用图像坐标比阈值（`rect.width < 3`），400px 的实际拖动只换算成约 0.55 图像像素，会被误判为"点了一下"，标注直接丢弃。

后果：小图/放大编辑时"画不出任何标注"，而大图正常，排查时容易误判成事件没绑定。

## 来源

- 本项目实现：`plugin/src/capture/tool-controller.js` 的 `endDraw()`，现按 `rect.width * zoom < CLICK_TOLERANCE` 判断。
- 同类判定（橡皮擦命中容差、手柄半径）也要按 `1 / zoomScale` 换算，保持一致。
