# ZTools 窗口问题规避

当 ZTools 插件出现窗口、焦点、遮罩、点击命中或子窗口问题，难以稳定复现，而用户希望参考已有实现快速规避时使用本技能。

## 工作原则

- 保持用户任务边界：解决可观察到的交互问题，不把任务扩展成全面排查宿主根因或无关重构。
- 当用户明确要求快速规避时，根因诊断可以降级为可选步骤；但仍要核对宿主版本、API 能力和最终产物。
- 优先复用 ZTools 生态中已经运行过的窗口生命周期实现，不自行发明一套新的窗口管理协议。
- 在说明开发入口前，先确认实际 ZTools 版本和可用 API。不能因为新版本源码中出现了某个菜单、命令或 API，就假设用户当前版本一定存在。

## 先参考实现，再修改

1. 明确可观察到的症状和期望的交互边界，判断问题属于主插件视图、临时遮罩，还是编辑器/选择窗口。
2. 搜索 `ZToolsCenter/ZTools-plugins` 以及项目本地依赖，寻找拥有相同窗口生命周期的插件。优先查看截图、图片标注、剪贴板图片编辑等会打开临时窗口的实现。
3. 将参考实现与当前宿主版本进行对照，核对 `createBrowserWindow`、`show`/`focus`、主窗口隐藏/显示、`sendToParent`、`getWindowType` 和 preload IPC 的实际行为。只使用源码、文档或本机已验证插件确认过的 API。
4. 在编辑前记录最小可迁移模式。通常需要迁移的是窗口所有权和消息流，而不是重写样式或到处增加点击事件。

## 推荐的窗口边界

当主插件视图受到焦点、命中测试、遮罩或隐藏窗口行为影响时，将有问题的交互隔离到独立浏览器窗口：

- 父插件负责业务流程、创建子窗口、隐藏/恢复主窗口以及处理最终结果。
- 子窗口负责编辑器或选择界面，并明确设置尺寸、最小尺寸、焦点和关闭行为。
- 子窗口通过结构化消息向父窗口返回成功、取消或关闭事件，然后自行关闭。当采用窗口隔离就是为了避免主页面状态混乱时，不要再用 `window.location.href` 把子窗口导航回主页面。
- 同时支持宿主环境和普通浏览器开发环境。对“是否处于子窗口”做防御式判断；宿主 API 不可用时保留简单的页面导航或原地处理降级路径。
- 不要把大体积图片 Data URL 或其他大数据直接放入子窗口 URL。优先写入 `localStorage` 或临时存储，只把短 key 放入 URL；URL 传值只能作为受控的降级方案。
- 保持 IPC/preload 桥接足够窄：preload 只负责接收宿主消息并转换为浏览器 `postMessage`，页面代码负责处理领域事件。

典型职责流如下：

```text
主插件 -> 创建子窗口 -> 隐藏/聚焦窗口
子窗口编辑器 -> 结构化结果/取消消息 -> 父窗口
父窗口 -> 恢复主窗口 -> OCR/翻译/后续动作 -> 关闭子窗口
```

如果截图命令不应让主插件留在截图界面后方，在目标 ZTools 版本支持时使用清单中的 `mainHide` 行为。

## 开发模式加载

只有在插件被登记并安装为开发模式后，`plugin.json.development.main` 才会生效。它不是一个可以直接粘贴地址的独立菜单。

对于提供官方开发者插件的 ZTools 版本：

1. 启动项目声明的本地服务，例如 `npm --prefix plugin run dev`。
2. 打开官方 `ZTools 开发者工具` 命令。
3. 导入项目的 `plugin.json`，选中项目并点击“安装（开发模式）”。
4. 回到 ZTools，执行能够触发问题的真实插件命令。
5. 修改代码后，如果宿主没有自动获取更新，执行 `重载开发中插件`。

如果找不到这些命令或控件，先确认 `ztools-developer-plugin` 是否安装，以及当前客户端是否支持开发项目。不要让用户反复寻找未经确认的“开发/调试设置”入口。

## 快速验证与交付

当用户明确要求快速修改、快速验证时：

- 构建插件，并确认开发入口或构建文件可以访问。
- 只验证高信号不变量：服务有响应、子窗口能打开、问题区域可点击、子窗口能回传结果、取消/关闭能恢复父窗口状态。
- 对难以在单元测试中复现的宿主窗口行为，优先进行真实 ZTools 客户端冒烟验证，不强行新增大规模测试套件。
- 只部署到用户本机的 ZTools 开发安装，不发布到官方插件仓库；除非用户另行明确授权。
- 交付时说明本地启动命令、插件路径、开发地址和第一次应执行的交互，并说明尚存风险。不要声称已经理解宿主根因或永久修复了宿主缺陷。

## 停止条件

当参考实现能够满足可观察行为，且本机冒烟验证通过后，停止扩大排查范围。只有在参考 API 不可用、子窗口无法创建、消息丢失，或规避方案破坏了明确要求的降级路径时，才继续深入调查。
